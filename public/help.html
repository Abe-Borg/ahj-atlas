USER GUIDE

From address to evidence.

Local project research for engineers and architects.

Start a project

  1. Open API & spending and enter your Anthropic API key. The connection checks access to the configured models. Web search must be enabled in your Anthropic Console.
  2. Enter the complete project address and choose your discipline, or select Other — enter your discipline and type your specialty. Add the scope, building use, and permit date when known.
  3. Choose Research now or Research later, set the budget, and start.
  4. Inspect findings, evidence passages, and questions to resolve. Download a PDF, Excel workbook, or JSON research record.

Real-time and batch

Research now begins immediately. The app updates as each research stage and source reading finishes.

Research later uses Anthropic’s Message Batches API. Model token prices are 50% lower; search fees are unchanged. Research has dependent stages, so it requires several batch submissions. Each batch has a 24-hour processing window and can expire. A complete report can take longer than 24 hours.

Keep the local application running to advance stages automatically. Closing the browser is fine. If the computer sleeps or the backend stops, batches already submitted continue at Anthropic. Reopen the app and reconnect your key to retrieve results and continue.

Fire protection and NFPA standards

Fire protection research screens individual NFPA standards for your project, including system-specific candidates based on building use and notes. Each finding distinguishes applicability from evidence status and gives the adopted edition and source when established. A standard on the checklist is not automatically a legal requirement. Unknown editions remain unconfirmed.

For an older report, open Codes & standards → Research NFPA standards. This starts paid, focused research and a new report within your total budget. It retains completed jurisdiction/contact work, saved sources, spending and cumulative search/read limits. Choose real-time or batch in the dialog. Your previous report remains available while research runs.

PDF reports include a separate NFPA section, and Excel exports include an NFPA standards worksheet. Add system details such as battery chemistry, suppression type and fuel storage through the normal project-context update when known.

Project chat

A project name is required when creating research. Within a saved project, open Chat with AI to ask Sonnet 5, using high reasoning effort, about the report, sources, research notes and saved question answers. Each project has its own conversation and draft. Switching projects keeps pending replies with their original project.

The assistant can inspect all saved records for that project and cite sources you can open. It uses saved evidence; start a research round for new public-source investigation. Chat does not directly edit the report or question answers.

Each message uses real-time API pricing and shares the project and daily spending allowances. Open Spending & limits to set the reply allowance (default $1, maximum $5) or update the project allowance. Replies allow up to four requests, eight project lookups and five minutes. Stop reply prevents more work after the current request finishes and its cost is recorded. Conversations are saved locally and sent with relevant project context to Anthropic when you send a message. Restarting the app does not automatically resend interrupted messages.

Answering questions

Each Questions to resolve card lets you enter what you know and choose Save answer, or Dismiss a question that is not a priority. The open count updates immediately. Expand Answered & dismissed to edit an answer or reopen a question. Responses are saved with the project and included in exports.

Saving does not start research or use Claude credits. Choose Research with saved answers to start another round with your answers and dismissals. Newly saved information reopens research so its implications can be checked. Answers remain user-provided context; dismissing a question does not establish compliance or non-applicability. All fields under Add project context, including Additional context, are optional.

Understanding evidence

Source-supported: the model identified support and the app matched a quoted passage to retrieved source text. This is not an independent certification of legal applicability or design compliance.

Conditional: the finding depends on an assumption or unresolved jurisdiction. Conflicting: sources disagree. Unconfirmed: the evidence or exact edition has not been established.

Search discoveries are listed separately from sources read as evidence. Scanned PDF pages can be inspected visually, but a visually transcribed quotation remains unconfirmed until readable evidence supports it. Current public contacts, effective dates, transition rules, and adopted editions should be confirmed with the responsible authority when unclear.

Spending controls

The app uses Sonnet 5 for research and Opus 5.5 for an evidence check and the final report. Contacts use medium effort; jurisdiction and code research use high effort; both Opus stages use medium effort. The evidence check can investigate missing or conflicting sources before the report is written. Model rates are based on Anthropic’s documentation checked September 24, 2026.

The project budget and daily allowance stop new requests. Pending requests reserve funds, and research holds allowance for the final report across your projects: $2.48 in real-time mode or about $1.26 in batch mode. These holds appear in the cost display. Stopping a project releases its unused final-report hold. Native search has variable internal token usage, so a request already in flight may exceed its estimate. The provider invoice is authoritative.

Research is bounded to 40 searches, 100 source reads, 12 requests per stage, and at most two active local research tasks. Research responses allow up to 60,000 output tokens; the final report allows 100,000, including thinking. These are ceilings, not targets or fixed charges. Larger ceilings require larger spending reservations, so the default budget may need adjustment. The Opus evidence check has its own limit of 6 requests, 8 searches and 12 source reads within the project totals. Real-time work has an active research allowance of 15 minutes; a response already in flight can finish afterward, with a 30-minute response deadline. Batch waiting time has separate provider deadlines.

If an allowance is reached, increase it or choose Finish with saved evidence. A partial report still requires a paid final review. The app never silently increases your budget or switches batch work to standard pricing.

Stopping, resuming, and uncertain requests

Stop research prevents new requests and asks Anthropic to cancel pending batches. In-flight work can still complete and be billed. The app keeps polling known batches to reconcile results.

If a connection ends during submission, the app retains the pending allowance instead of submitting a duplicate. For a batch, find its ID in your Anthropic Console and use Reconcile original batch after it finishes. The app matches the exact request identifier before importing. After the 29-day batch-result retention window, or if results cannot be accessed, the app stops automatic retrieval and keeps the reservation for manual reconciliation.

When automatic reconciliation is unavailable, open Activity → Resolve uncertain charge. Confirm in the Anthropic Console that the original request finished, failed, or was canceled, and record its charge. Do not release a reservation for work whose outcome is still unknown.

Adding project context or a follow-up question when resuming reopens the research stages so the findings can be checked. When all research stages are already complete, continuing without new context runs only a paid final report using the saved sources. Older saved reports are preserved; explicitly continuing an older project adds the new Opus evidence check when needed. Recorded costs are retained.

Diagnostics and troubleshooting

Open API & spending → Diagnostics to inspect saved progress, request history, timing, usage, and errors. Choose a project or the entire workspace, then select Download diagnostics to save a troubleshooting file.

Diagnostics are local and persist after restarting. The latest 5,000 detailed events are retained. Older projects still show saved request summaries, but detailed tracing starts with version 1.2.0. Viewing or downloading diagnostics does not spend Claude credits.

Keys, prompts, source text, and model thinking are excluded. Review error details before sharing the file; nothing is uploaded automatically.

Your data and API key

Research is stored in the app’s data folder. If you put the app in a synced folder, that folder’s normal sync settings apply. The local server accepts connections only from this computer.

Your key is held in backend memory by default. Optional Windows storage protects it with your Windows account and saves the encrypted credential in Local AppData, outside the app’s project folder. It is not saved in browser storage, reports, or the research database.

Project details and relevant source content are sent to Anthropic to perform research. The address can also be sent to the US Census geocoder when applicable. Public research URLs are retrieved from their original sites. Batch requests are stored by Anthropic during processing; consult its current data-retention documentation for details.

The isolated research browser uses a fresh profile without your browser sign-ins. It reads public pages and does not log into services, submit applications, send emails, or purchase documents.

Launch and stop

Double-click Start AHJ Atlas.cmd to open the application. Double-click Stop AHJ Atlas.cmd to finish in-flight work and stop the local background process. Saved projects remain available.

Requirements: Node.js 24 or newer, an internet connection, and an Anthropic API account with access to Sonnet 5 and Opus 5.5. An installed Edge or Chrome browser enables the optional dynamic-page reader.
