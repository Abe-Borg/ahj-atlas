# AHJ Atlas 1.13.0 — Chat attachments and stronger evidence checks

This release includes all changes since 1.12.1, adding documents to chat and improving standards research, saved-answer handling, source access, and exported evidence.

## What's new

- **Attach documents to a chat message.** Choose **Attach document** or drop files on the message area. Each message can carry up to five PDF, HTML or plain-text files, up to 50 MB each. Atlas adds them to the project's Sources and links them to the sent message. Adding a document is free; a chat reply uses the selected model and incurs its usual API cost. A document stays in Sources even if you remove its attachment or never send the message. Word files and PDFs without extractable text remain unsupported.
- **Screen referenced standards for more disciplines.** Codes & standards now includes a referenced-standards checklist for supported disciplines beyond fire protection, with focused follow-up research for their standards. Findings still need source-linked applicability and adopted-edition evidence. Fire protection retains its NFPA checklist and Canadian standards coverage.
- **Set the building use explicitly.** New projects default to **Hyperscale data center**. Choose **Other — enter building use** to describe another use.

## What's improved

- **Stronger checks before a finding is source-supported.** Standards adoption evidence must include adopting or in-force wording; negated adoption wording does not qualify. General code editions must appear in supporting quotations, and contact phone numbers must appear in fully read supporting sources. Unsupported findings become questions to confirm.
- **Fresh search and read allowances for a new research round.** Continuing with new context or saved answers, correcting a location, or starting focused standards research resets the round's allowances. Ordinary continuation keeps its remaining allowance. The continuation dialogs explain what remains and whether a new round starts.
- **Keep the final review's retrieved passages.** The last review request retains the earlier lookups, including when a long conversation must be rebuilt, so a decisive exception is not lost before the report is written.
- **Saved answers reach the stages that need them.** While answers or dismissals await research, use **Research with saved answers** to reopen every stage. A focused standards update cannot consume them instead. An answer mentioning another finding no longer silently resolves that finding's question.
- **Ask Atlas cards change only what they name.** Applying a report note or a card for another question leaves the question you asked about open. Answer or dismiss that question on its own card when it is settled.
- **Better access through the optional page renderer.** Edge or Chrome loads the requested host using its browser network stack while preserving the public-address checks and response-size limit. A refused page is remembered separately from a site that refuses all pages, and the error explains the remaining source-reading options.
- **Clearer dates and uncertainty in exports.** Rediscovering a URL no longer gives old source text a new retrieval date. Sources distinguish Retrieved, Discovered, Inspected and Added dates. PDF findings show their evidence status; PDF and Excel flag quotations that need confirmation and distinguish report generation from export time.

Source users also gain an offline accuracy scorer at `scripts/score-evaluation.mjs`, with an example answer key and a documented evaluation procedure. It compares JSON project exports against independently checked answers; it makes no API requests. It is a source-development tool, not a new installed-app screen.

## Limitations

Existing reports are not automatically rerun or rewritten. Previously dismissed questions stay dismissed and can be reopened on Overview. Research allowances and source-access restrictions still apply; browser rendering cannot guarantee access to a blocked website. Stricter evidence checks do not establish research accuracy, and an independent accuracy evaluation remains necessary.

Automated checks use synthetic providers. Findings, citations, and exported reports require professional review and do not establish code compliance, legal applicability, or completeness. Costs remain estimates; your Anthropic invoice is authoritative.

## Updating and Windows installation

From 1.7.0 or later, use **API & spending → App updates → Check for updates**, then **Download update** and **Restart and install** after this release is published. Earlier versions require a manual installation. Back up your workspace before upgrading and use the same Windows account to keep saved projects and the remembered credential.

For a manual installation, download `AHJ-Atlas-1.13.0-Windows-x64-Setup.exe` and `SHA256SUMS.txt` from this release, verify the SHA-256 checksum, close AHJ Atlas, and run the installer. The installer includes the app runtime. The optional JavaScript page renderer uses an installed Edge or Chrome browser.

The installer and executable are unsigned. Windows may show **Unknown publisher** or a SmartScreen warning. Confirm the download comes from this project's GitHub Release and verify its checksum before choosing whether to run it. Do not disable Windows security protections. A matching checksum confirms the published bytes; it does not prove the publisher's identity.

See the [Windows installation guide](https://github.com/Abe-Borg/ahj-atlas/blob/main/docs/windows-installation.md) for installation, in-app updates, backup, uninstall, and checksum steps.
