# AHJ Atlas 1.12.0 — Economy chat and resource diagnostics

This release includes all changes since 1.11.0, adding a lower-cost chat option and clearer diagnostics for slow or interrupted work.

## What's new

- **Choose Economy for straightforward chat.** Project chat now offers **Economy — Claude Haiku 5.5, medium reasoning** for summaries and questions using saved evidence. It starts with a smaller evidence package to reduce input costs and retains source lookups, web research, citations, and proposed actions. Standard remains the default; research, evidence checks, and final reports keep their existing models.
- **Keep conversations when changing reply depth.** Earlier completed answers carry forward when switching models. Requests already underway keep their submitted model and pricing. An Economy decline offers **Try again with Standard**; retrying requires your choice and creates a new paid reply.
- **Estimate Haiku costs by prompt size.** Cost estimates account for Haiku's higher rates above 100,000 prompt tokens, including cached input. When returned usage does not identify the tier reliably, Activity labels the conservative charge as estimated. Previously recorded costs remain intact.
- **See when the computer or provider was constrained.** Diagnostics now show **Starved / throttled**, per-project counts, and **Resources and starvation** details. The app samples its event-loop delay, pauses, CPU, and memory while running, relates those readings to timed operations, and counts provider rate-limit and overload responses once per request. These readings help distinguish host constraints, provider responses, and application allowance exhaustion.

## Limitations

Economy's smaller opening context can omit details until lookup tools retrieve them; compare difficult jurisdiction and adoption questions with Standard. Its context can grow into the higher pricing tier. Costs are estimates, and your Anthropic invoice is authoritative. Automated regression checks use synthetic providers and do not establish live model access or research accuracy.

Resource readings describe observed conditions; overlap with an operation does not prove what caused a delay. Sampling stops when the app closes and does not change scheduling, retries, or research allowances. Findings, citations, and exported reports still require professional review and do not establish code compliance, legal applicability, or completeness.

## Updating and Windows installation

From 1.7.0 or later, use **API & spending → App updates → Check for updates**, then **Download update** and **Restart and install** after this release is published. Earlier versions require a manual installation. Back up your workspace before upgrading and use the same Windows account to keep saved projects and the remembered credential.

For a manual installation, download `AHJ-Atlas-1.12.0-Windows-x64-Setup.exe` and `SHA256SUMS.txt` from this release, verify the SHA-256 checksum, close AHJ Atlas, and run the installer. The installer includes the app runtime. The optional JavaScript page renderer uses an installed Edge or Chrome browser.

The installer and executable are unsigned. Windows may show **Unknown publisher** or a SmartScreen warning. Confirm the download comes from this project's GitHub Release and verify its checksum before choosing whether to run it. Do not disable Windows security protections. A matching checksum confirms the published bytes; it does not prove the publisher's identity.

See the [Windows installation guide](https://github.com/Abe-Borg/ahj-atlas/blob/main/docs/windows-installation.md) for installation, in-app updates, backup, uninstall, and checksum steps.
