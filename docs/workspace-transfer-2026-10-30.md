# Sharing a workspace with your team — October 30, 2026

**Before.** Every project lived only in the SQLite database on the computer that ran it. Exports were per project (PDF, Excel, Excel essentials, JSON) or addresses only, and none of them could be loaded back. Moving projects to a teammate meant copying the whole data folder, which replaces their workspace and only works while both apps are closed.

**Now.** **Export workspace** in the sidebar saves every project to one `.ahjatlas` file. **Import workspace** lists the file's projects beside the importer's own and copies the ones they choose, so a team can share reports, sources, research progress and chat, and keep working on them.

## Design

- **The file.** A gzip-compressed SQLite database (`exportWorkspace` in `lib/workspace-transfer.mjs`). `node:sqlite`'s online `backup` takes one consistent snapshot of the live database, including committed transactions still in its write-ahead log, while research and chat keep running. The snapshot drops `diagnostics`, `deleted_project_charges` and the `settings` row (they describe the exporter's computer), adds a `workspace_export` table with `{application, format: 1, version, exported, projects}`, switches to `journal_mode=DELETE`, and is rewritten with `VACUUM` so the deleted rows leave no readable free pages. The API key is in the DPAPI credential file, never in the database. Filename: `AHJ Atlas workspace YYYY-MM-DD.ahjatlas` (`workspaceExportFilename`).
- **Why a database and not JSON.** Continuing a project needs every row as saved: stage conversations with their thinking signatures and encrypted search results, checkpoints, attempts and their pricing snapshots, tool runs, chat images as bytes. A database copy carries all of them with no second serializer to keep in step with the schema, and an export from an older version is upgraded by the same `Store` migrations that upgrade an installed workspace.
- **Export route.** `GET /api/workspace/export` builds the file in a `transfer-*` folder inside the data folder, sends it with `Content-Length`, and removes the folder once it is sent. Like the diagnostics download, it requires `Sec-Fetch-Site: same-origin`, so another site cannot start a download of the whole workspace. `GET /api/workspace` gives the export dialog its project count and the projects that cannot be imported yet.
- **Work that cannot move.** `heldWork` names a project whose saved state has a request `dispatching`, `pending` (a submitted batch), `received` but not applied, or `unknown` (an uncertain charge), or a chat turn still `running`. That work belongs to the exporter's Anthropic account: the importer could not finish it, poll the batch, or reconcile the charge, and the scheduler would otherwise poll a batch it does not own. Such projects stay in the file but are marked **Cannot be imported**, and the server refuses them even if asked directly.
- **No automatic spending.** The research worker dispatches any project whose status is not terminal, and saving an API key requeues `needs_key` projects. An imported project in any status other than `complete`, `partial`, `canceled`, `attention` or `failed` is set to `attention` with a note to choose **Continue research**; one with `cancel_requested` set becomes `canceled`, as the worker would make it. Stage states and conversations are kept, so `resume` continues where the exporter stopped. The project's own `updated` time is kept so it still matches the file it came from.
- **Staging an import.** `POST /api/workspace/import` takes the raw file with the app token (`server.mjs`, beside the document and image uploads) and `stageImport` saves it to a new `transfer-*` folder. An upload over 2 GB is read to the end and dropped, so the 413 reaches the browser instead of a reset connection; decompression stops past 8 GB. The file must start with the gzip magic, decompress to a file with the SQLite header, and, opened read-only with `trusted_schema=OFF`, have no triggers or views (AHJ Atlas creates none), have `settings`, `projects` and a valid `workspace_export` note from this version or older, and pass `integrity_check`. Only then is it opened with `Store`, which upgrades its schema, and checked with `foreign_key_check`. Errors are plain: not an export, damaged, too large, or exported by a newer version (update first).
- **Preview.** Each project is described with its last activity (latest of the project row, Activity, chat, notes and answers) and a fingerprint of its saved records (counts and latest times of Activity, chat, attempts, sources, notes, answers and images). Import notes (Activity kind `transfer`) are left out of both, so a project imported unchanged reads **Already in your workspace and up to date** in that file and in a later export of it from the other side. A project ID that does not match the app's route pattern is not importable.
- **Applying.** `POST /api/workspace/import/<id>` with `{add, replace}`. The server re-checks every choice against the current workspace: an added project must still be absent, a replaced one still present, and a replaced project must have no work running here (the delete route's in-memory check, now `projectBusy` in `createServices`, plus `heldWork` on the saved rows). `applyImport` attaches the staged file, then in one `BEGIN IMMEDIATE` transaction removes each replaced project's rows (`Store.removeProjectRows`, shared with **Delete project**) and copies the chosen projects' rows table by table in foreign-key order, keeping row order and every key except Activity's auto-increment IDs. A failure rolls back and changes nothing.
- **Charges on replace.** Before a replaced copy's rows go, the charges of its attempts that the incoming copy does not also carry move to `deleted_project_charges`. The importer's own chat or research on their copy stays in their spending totals; attempts both copies share come back with the incoming copy and are not counted twice.
- **One staged import.** The service keeps at most one staged import. A new upload replaces it, closing the dialog sends `DELETE /api/workspace/import/<id>`, applying removes it, closing the app removes it, and `transfer-*` folders left by a crash are removed when the workspace next opens.
- **Desktop.** `desktop/downloads.mjs` accepts `/api/workspace/export` with no parameters and the `.ahjatlas` extension, saved through the native Save dialog with the **AHJ Atlas workspace** filter. Import uses the page's own file input, which Electron shows as the native Open dialog.
- **UI.** Sidebar **Export workspace** (hidden with no projects) and **Import workspace** (always shown, so a new teammate can start from a file). The import list reuses the address export's checklist styles: new projects checked, up-to-date and held projects disabled with the reason, differing projects unchecked with a note and a warning when the local copy has newer activity. Replacing asks for confirmation. A file chosen after the dialog closed or after another file is discarded.

## Limits and choices

- Importing chooses one copy per project; it does not merge two people's chats, notes or answers. Adding a second copy under new IDs would mean rewriting attempt, chat turn, note and source keys throughout the saved rows, and was left out.
- Export always includes the whole workspace; the importer chooses projects.
- Imported recorded costs count in the importer's **API & spending** totals, including **Today** for charges the exporter recorded that day.
- Continuing an unfinished stage under another Anthropic account sends that stage's saved thinking signatures and encrypted search results with the importer's key. This was not checked with live keys from two accounts. If a continued request were refused, the stage would stop as blocked, and **Continue research** restarts a blocked stage from its saved checkpoint.

## Verification

- `node --test tests/workspace-transfer.test.mjs`: the file is gzip-compressed SQLite with the export note and no diagnostics (not even in free pages), settings or deleted-project charges; the download needs same-origin fetch metadata; a round trip reproduces every row of a finished project (report, sources, stages, chat, attempt, tool run, image bytes, note, answer, links, chat evidence); unfinished research arrives paused and a canceling project canceled; a pending batch, an uncertain charge and a running chat reply are held and refused; nothing changes before applying; a second upload of the same file reads up to date; replacing takes the newer copy and keeps the importer's own charges without double counting; a project with work running here cannot be replaced; non-exports, truncated files, newer-version files, files with triggers or views, plain workspace databases, empty uploads and oversized uploads or databases are refused; staging folders are removed after applying, discarding, a newer upload, closing, and at the next start after a crash.
- `node --test tests/desktop-downloads.test.mjs`: the desktop accepts the workspace download only without parameters, saves it through the **AHJ Atlas workspace** filter, and refuses another extension.
- `node tests/workspace-transfer-ui.mjs`: export dialog count and still-running notice, the downloaded file, an empty workspace offering only import, a refused file, preview states with escaped names, discard on close, import into the sidebar, up to date and replace (with confirmation) on a second file, and mobile layout.
